# PT-006 · Posible Inyección SQL en Drupal Core (Drupalgeddon)

- Estado: posible
- Autor / revisor / fechas: DQH / pendiente / 2026-10-04
- Activo / instancia / snapshot / IP / puerto / servicio / versión: 192.168.18.130 / 80 / Apache / Drupal 7
- Hipótesis / sesión de origen: Identificación de Drupal 7 mediante escaneo web y whatweb. Posible vulnerabilidad a CVE-2014-3704 (Drupalgeddon) según resultados de searchsploit.
- Severidad y razonamiento: 9.8 (Crítica) - Permite la inyección SQL, lo que facilita obtener acceso de administrador al CMS o ejecutar código.
- CVSS: N/A (Pendiente de validación)
- CVE / CWE: CVE-2014-3704 / CWE-89

## Descripción técnica y causa

Drupal 7.x anterior a la versión 7.32 contiene una vulnerabilidad en su API de abstracción de bases de datos que no sanitiza adecuadamente los arreglos en las consultas parametrizadas. Esto permite inyectar sentencias SQL arbitrarias.

## Descubrimiento y validación

Se identificó la versión mayor de Drupal (7) durante la enumeración web (Whatweb, Wappalyzer). Las consultas en `searchsploit` resaltan esta vulnerabilidad como un vector común en Drupal 7. Requiere comprobación activa.

## Reproducción

Pendiente de validación técnica. Se probará un exploit público para intentar la creación de un usuario administrador en la base de datos de Drupal.

## Evidencias

Pendiente de asignación de evidencias de la captura del CMS.

## Impacto

Un atacante podría alterar o leer la base de datos completa. Comúnmente se utiliza para inyectar un nuevo usuario con rol de Administrador, desde el cual se puede habilitar la ejecución de código PHP (módulo PHP Filter) para comprometer totalmente el sistema.

## Remediación y comprobación

Actualizar a una versión de Drupal que no sea vulnerable a este fallo.
